Theoretical Discussion: Statistical Properties & One-Way vs Hash Functions

Exam Report Analysis

1. Subgroup Structure: G = (1, 5) vs Full Generators

By Hasse's Theorem, the number of points on y² ≡ x³ + 7 (mod 17) satisfies |N - (17 + 1)| ≤ 2√17 ≈ 8.24. Counting explicitly yields |E(F₁₇)| = 18 (17 affine points plus the Point at Infinity ∞).

  • Why G = (1, 5) visits only 9 points: Since 18 = 2 × 3², Lagrange's Theorem states that any point has an order dividing 18. For G = (1, 5), we obtain 4G = (12, 1) and 5G = (12, 16) = -4G, meaning 9G = ∞ (order n = 9, cofactor h = 2). For k = 6, the Toy Public Key is Q = 6G = (5, 8).
  • Full Curve Generators: Selecting G = (15, 13) or G = (6, 6) yields order n = 18 (cofactor h = 1), visiting all 17 affine points before reaching ∞ at 18G. (In Ethereum's real secp256k1, the group order is a 256-bit prime, so every non-zero point has cofactor h = 1).

2. Coordinate Frequency & Bijective Cube Property

Comparing the empirical distribution of x and y across all 17 affine points reveals a striking algebraic asymmetry:

  • Perfect Uniformity of y: In GF(17), the multiplicative group has order p - 1 = 16. Since gcd(3, 16) = 1, the cubing map x → x³ (mod 17) is a bijection. Thus, for every single y ∈ {0, ..., 16}, there exists a unique x ≡ (y² - 7)11 (mod 17). Consequently, every y value in 0..16 appears exactly once!
  • 2-to-1 Clustering of x: Because (±y)² ≡ y² (mod 17), each valid x with y ≠ 0 generates two points (x, y) and (x, 17 - y). Hence, 8 values of x appear twice, x = 3 appears once (at y = 0), and 8 values of x never appear (where x³ + 7 is a quadratic non-residue).

3. Bit Distribution, Correlation & Avalanche Effect

Evaluating the map k → Q = kG across sequential scalars demonstrates key statistical behaviors:

  • Uncorrelated Input/Output: The linear Pearson correlation coefficients r(k, xₖ) and r(k, yₖ) are virtually zero (r = 0.000 on a symmetric cycle because xₖ = xn-k and yₖ + yn-k = 17). Knowing kG provides no linear clue about k.
  • Bit Uniformity & Avalanche-like Jumps: Incrementing k by 1 flips on average ~45%–52% of the binary bits of (x, y) and causes large geometric jumps across the 17 × 17 plane. However, unlike a true random function, the bit distribution is constrained by the finite field boundary (values 0..16 require 5 bits, so the MSB b₄ is only 1 when the coordinate is 16).

4. One-Way Functions (ECDLP) vs Cryptographic Hash Functions

While both are easy to compute forward and computationally infeasible to invert, their mathematical roles in Ethereum differ fundamentally:

  • Meaningful for ECC One-Way Functions: Preimage hardness (recovering k from Q = kG requires O(√n) via Pollard's rho) and input-output decorrelation are vital. Crucially, ECC preserves algebraic structure (additive group homomorphism: k₁G + k₂G = (k₁ + k₂)G). This homomorphism enables public-key verification in ECDSA digital signatures and ECDH key exchange.
  • Specific to Cryptographic Hash Functions (Keccak-256): Hash functions take arbitrary-length inputs and produce fixed-size outputs that destroy all algebraic structure (homomorphism in a hash function would allow trivial forgery and collisions). Strict bit-level uniformity (P(bit=1) = 0.5), collision resistance, and the Strict Avalanche Criterion belong specifically to cryptographic hashes.
