1. Toy Cryptographic Scheme based on secp256k1 & EC-ElGamal

Finite Field GF(17) • y² ≡ x³ + 7 (mod 17) • G = (15, 13)

In Part 1 of Homework 1, we examined the elliptic curve y² ≡ x³ + 7 (mod 17), which forms a cyclic group of 18 points (17 affine points + the point at infinity ∞). Using base point G = (15, 13) (a generator of full order 18), we build a toy asymmetric encryption scheme analogous to EC-ElGamal.

Algorithm Steps & Key Roles

  • Key Generation (Bob): Bob chooses a private scalar kB from a restricted range (e.g., 1 ≤ kB < 18) and computes his public key QB = kB · G.
  • Encryption (Alice): To encrypt a message point M (which is a valid point on the curve representing character encoding or numerical payload), Alice picks a random ephemeral integer r, computes ciphertext component C1 = r · G, and shared secret mask S = r · QB. The second ciphertext component is C2 = M + S.
  • Decryption (Bob): Bob receives (C1, C2). He computes his shared secret mask S' = kB · C1 = kB(rG) = r(kBG) = rQB = S, and recovers the plaintext message point by point subtraction: M = C2 - S' = C2 + (-S').

2. The Caesar Cipher & Comparative Analysis

Substitution Cipher • Key Space = 26

The Caesar Cipher is a classic substitution cipher that encrypts plain-text by shifting each letter forward by a fixed number of positions k ∈ [0, 25] modulo 26.

3. Statistical Cryptanalysis of the Caesar Cipher

Chi-Squared Goodness-of-Fit • Letter Frequency Analysis

Because the Caesar cipher preserves the monographic letter distribution of the underlying language, we can recover the key automatically without brute-forcing all 26 options. By computing the Chi-Squared (χ²) statistic between the decrypted letter counts and known English letter frequencies:

χ² = ∑ (i=A..Z) [ (Oi - Ei)² / Ei ]

The shift key that minimizes χ² corresponds to the correct English plaintext.

Automated Statistical Key Recovery

Effectiveness, Sample Size Limitations & Alternative Approaches

  • Effect of Ciphertext Length (Law of Large Numbers): On long and medium texts (>100 characters), the empirical letter distribution converges closely to the theoretical English distribution, producing a sharp, unambiguous minimum in the χ² score at the true shift key. On very short ciphertexts (<15–20 characters), high sampling variance distorts letter counts (e.g., a short phrase lacking common vowels like 'E'), causing the monographic χ² test to occasionally misidentify the correct shift.
  • Exhaustive Key Search (Brute-Force): Since the key space is only 26, generating all 26 candidate plaintexts is computationally trivial (O(26)). However, automated brute-force still requires a statistical scoring function (like χ² or dictionary matching) to recognize the valid plaintext without human visual inspection.
  • Monogram Frequency vs. N-Gram Scoring: Standard frequency analysis treats letters as independent (unigrams). By contrast, n-gram scoring (bigrams like TH, HE, IN or trigrams like THE, AND, ING) evaluates the log-probability of adjacent character sequences: Score = ∑ log P(ci, ci+1). N-gram models capture Markovian language dependencies, making automated key recovery drastically more reliable on short ciphertexts and essential against general monoalphabetic substitution ciphers where the key space is 26! ≈ 4 × 1026.

4. Restricted Key Space Attack on Toy ECC

Baby-Step Giant-Step • Pollard's Rho • Exhaustive Search

The toy ECC scheme developed in Part 1 uses the secp256k1 curve equation over GF(17), but restricts the private key k to a small range (e.g., 1 ≤ k < 18) to make experiments computationally feasible.

Key Attack Vectors against Restricted ECC

  • Exhaustive Key Search (Brute Force): Because the private key space is only n = 18, an attacker can simply iterate k = 1, 2, ..., 17, compute kG, and match it against the target public key Q in microseconds.
  • Baby-Step Giant-Step (BSGS): A meet-in-the-middle algorithm that solves the ECDLP in O(√n) steps. For n = 18, √18 ≈ 4.2 steps, finding the key almost instantaneously.
  • Comparison with Caesar Statistical Attack: The Caesar statistical attack exploits redundancy and frequency skew in natural language plaintext. Conversely, the toy ECC restricted key space attack exploits the mathematical structure and small parameter size of the group, completely independent of plaintext language or structure.
  • Why Real ECC is Secure: Real-world secp256k1 uses a 256-bit prime group order n ≈ 1.15 × 1077. Exhaustive search or BSGS would require O(√n) ≈ 2128 operations—computationally infeasible with all physical energy on Earth.

Restricted Key Space vs. Structural Design Weaknesses

  • Weaknesses from Restricted Key Space: Even if the true secp256k1 prime field p = 2256 - 232 - 977 is used, restricting the private key k to a small interval [1, B] allows attackers to recover k in O(B) via brute-force or O(√B) via Baby-Step Giant-Step / Pollard's Kangaroo algorithm.
  • Weaknesses from Toy Scheme Design:
    1. Deterministic Character-by-Character Encryption (Electronic Codebook Mode): If a toy scheme encrypts each letter deterministically without a fresh random ephemeral scalar r per character, identical plaintext letters map to identical ciphertext points. The ECC scheme degenerates into a simple monoalphabetic substitution cipher and becomes vulnerable to the exact same Chi-Squared frequency analysis used against the Caesar cipher, regardless of how large the private key space is!
    2. Ephemeral Nonce Reuse: In EC-ElGamal, reusing the same ephemeral scalar r across two messages M1 and M2 yields C2,1 - C2,2 = M1 - M2, leaking the relationship between plaintexts without needing the private key.
    3. Small Subgroup / Toy Field: Operating over GF(17) restricts the message space to 18 points, allowing a complete precomputation lookup table (rainbow table) of all possible operations.
